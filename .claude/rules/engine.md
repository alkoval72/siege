# Правила движка `Siege.Engine`

Правило действует только для движка и его тестов.

## Источник истины

- Правила игры берутся из `docs/spec.md` §4-5, алгоритмы из `.planning/ARCHITECTURE-TARGET.md` §4. Перед изменением правила прочитай нужный раздел.
- Если нужно отклониться от базовых правил, сначала правится `spec.md` (с записью в журнал решений), потом код.

## Чистота и неизменяемость

- В `Siege.Engine` нет `PackageReference` и `ProjectReference`: только BCL. Нет ASP.NET, EF, Serilog, ввода-вывода, `DateTime.Now`, `Random`. Жребий первого хода приходит снаружи.
- Типы состояния: `record` или `readonly record struct`, коллекции `IReadOnly*` или `System.Collections.Immutable`. Методы не изменяют аргументы, `Apply` возвращает новое состояние.
- Координаты осевые `(q, r)`, направления берутся из `Hex.Directions`. Радиус поля приходит из `GameOptions` и константой не зашивается.
- Фишки называются по поведению (`Sovereign`, `Climber`, `Jumper`, `Scout`, `Runner`). Тематические названия (король, рыцарь) в коде и комментариях движка не используются.

## Документация

- У каждого публичного типа и члена есть XML-doc на русском: `<summary>`, а там, где смысл неочевиден, ещё `<param>` и `<returns>`.
- Если член реализует правило игры, в `<summary>` указан раздел `spec.md`.

## Тесты

- Каждое новое или изменённое правило сопровождается тестами. Пиши их через skill `engine-test`: допустимые и недопустимые случаи, край поля.
- Тесты лежат в `Siege.Engine.Tests/<Тип>Tests.cs`, имена методов в формате `Метод_Условие_Результат`, табличные случаи через `[Theory]`.

## Проверка

После правки: `dotnet build server/Siege.sln`, тесты затронутого класса через `--filter`, затем все тесты и `dotnet format server/Siege.sln --verify-no-changes`.
