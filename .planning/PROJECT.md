# Siege

## What This Is

Siege это браузерная сетевая стратегия для двух игроков на гексагональном поле радиуса 10 (331 клетка). Механика близка к известной игре про насекомых, а оформление, тексты и графика собственные, в средневековой теме. Игроки: владелец, семья и друзья. Режимы: онлайн 1 на 1 по ссылке-приглашению и локальный «два игрока за одним экраном».

Сервер является единственным источником истины: движок правил `Siege.Engine` (C#, чистая библиотека) проверяет ходы, ASP.NET Core 8 и SignalR рассылают состояние, PostgreSQL (EF Core) хранит партии как список ходов. Клиент на Vue 3 + TypeScript + Pinia рисует поле в SVG и правил игры не знает.

## Core Value

Двое игроков могут сыграть полную партию от старта до победы или ничьей, и каждый ход проверяется движком правил на сервере.

### Out of Scope

- Мобильная версия и адаптивная вёрстка: целевой экран только широкоформатный (1920×1080, масштабирование до 1366×768).
- Бот-соперник: в MVP играют только люди.
- Расширения набора фишек: в MVP только базовый набор из пяти типов, но движок проектируется с точкой расширения (`REQ-engine-extensibility`).
- Регистрация с email и паролем, рейтинги, турниры: достаточно анонимного входа по имени.
- Таймеры хода и контроль времени: автопроигрыша по отсутствию игрока нет.
- Отмена хода: не нужна для MVP.
- Режим наблюдателя и интерфейс повтора партии: ходы хранятся с первого дня, но интерфейса повтора в MVP нет.
- Ничья по повторению позиции: отложена на период после MVP (решение `spec.md` §12).
- Звуки и чат: не входят в MVP (простые анимации перемещений входят).
- Публичный релиз и монетизация: перед ними нужна консультация юриста из-за близости механики к известной игре.
- Кнопка «сдаться»: решение не принято (`ARCHITECTURE-TARGET.md` §13 называет её возможным дополнением, в `spec.md` её нет), в требования не включена.

## Context

**Цели владельца** (`spec.md` §1): играбельная игра для семьи и друзей и одновременно отработка полного цикла работы с Claude Code (spec, архитектура, `CLAUDE.md`, hooks и skills, разработка с тестами). Разработчик один, графику готовит с помощью Claude.

**Критерий успеха**: критерии приёмки MVP из `docs/spec.md` §13 (`REQ-mvp-done`): полная партия локально и по сети, все ходы проверяются сервером, тесты движка проходят (разрыв группы, протискивание, край поля), подсветка показывает допустимые и недопустимые клетки со значками, партия не теряется при обрыве соединения.

**Источники истины.** `docs/spec.md` (v0.2) задаёт правила игры и является источником истины для движка. `.planning/ARCHITECTURE-TARGET.md` (v0.1) задаёт компоненты, контракты REST и SignalR, схему БД и алгоритмы движка. При расхождении документов или кода и документов агент останавливается и спрашивает владельца, молчаливых выборов нет.

**Текущее состояние кода** (карта `.planning/codebase/`, коммит `c3a1544`): готов только каркас M0. В `server/Siege.Engine/` один тип `Hex`, в `server/Siege.Engine.Tests/` его тесты (10 методов), в `client/` Vue 3-заглушка и `game/hex.ts` с формулой пикселей. Нет `GameState`, `Game.Apply`, `GetLegalMoves`, проекта `Siege.Server`, БД, `docker-compose.yml`, Pinia и SignalR-клиента в `package.json`.

**Работа через GSD.** После инициализации источником истины для плана и состояния становится `.planning/`; `docs/plan.md` и `docs/progress.md` замораживаются после сдачи ДЗ модуля 2. Этапы идут по M0-M7 из `ARCHITECTURE-TARGET.md` §10. Ответы GSD на русском, `commit_docs: false` (коммитит владелец; решение, коммитить ли `.planning/`, тоже за ним).

**Нерешённые вопросы по правилам.** Отчёт `.planning/INGEST-CONFLICTS.md` содержит шесть предупреждений, на которые отвечает только владелец (поведение `Scout`, формула высот `Climber`, статус `spec.md` против `ARCHITECTURE-TARGET.md` §12, учёт пропусков в правиле 4-го хода и выставление у высокой стопки, идентификаторы статуса партии, формулировка условия выставления). ## Constraints

- **Tech stack**: движок на C# без зависимостей (в `Siege.Engine.csproj` нет `PackageReference` и `ProjectReference`), сервер ASP.NET Core 8 + SignalR + EF Core + Npgsql, Serilog, PostgreSQL, клиент Vue 3 + TypeScript + Pinia + SVG, запуск через Docker Compose. Причина: стек и стандарты Alliance, чистота движка нужна для воспроизводимости и тестов.
- **Архитектура**: сервер единственный источник истины; состояние движка неизменяемо (`Apply` возвращает новое состояние); ход проверяется членством в `GetLegalMoves`, второго набора правил нет; слой Repository поверх EF Core не делается. Причина: одна истина, простые повторы и отладка.
- **Клиент**: правил не знает, допустимые ходы берёт из `legalMoves`; красная подсветка вычисляется только для отображения и правилом не является. Причина: два набора правил разойдутся.
- **Тема**: названия и картинки фишек живут в `theme.json` клиента, в движке и компонентах только поведенческие имена (`Sovereign`, `Climber`, `Jumper`, `Scout`, `Runner`). Причина: смена оформления не должна трогать правила.
- **Масштаб**: одна копия сервера, активные партии в памяти (выгрузка через 30 минут без подключений). Причина: достаточно для семьи и друзей, несколько серверов не поддерживаются.
- **Процесс**: вся работа в ветке `develop`, агент не делает `git commit` и `git push`, после каждого блока работ проверки зелёные (`dotnet build/test/format`, `lint`, `type-check`, `test:unit`), любое изменение правил движка сопровождается тестом (skill `engine-test`), зависимости (`pinia`, SignalR-клиент) добавляются только с согласования. CI/CD не используется и не создаётся по умолчанию.
- **Безопасность**: токен игрока (32 байта) хранится в `localStorage`, в БД только SHA-256 хеш, токен не передаётся в адресе; чтение и правка файлов окружения запрещены.
- **Юридическое**: только оригинальные названия, тексты, графика и логотип (`spec.md` §9), заимствовать у оригинальной игры нельзя.
- **Язык и оформление**: комментарии, XML-doc, документация и коммиты на русском, идентификаторы на английском; длинное тире (U+2014) не используется.
- **Платформа**: .NET 8 выходит из поддержки 2026-11-10; переход на .NET 10 (LTS) запланирован, момент перехода решает владелец (см. `STATE.md`).
