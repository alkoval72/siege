# Requirements: Siege

**Defined:** 2026-10-27
**Core Value:** Двое игроков могут сыграть полную партию от старта до победы или ничьей, и каждый ход проверяется движком правил на сервере.

Источник: `docs/spec.md` v0.2 (правила игры, источник истины для движка) и `.planning/ARCHITECTURE-TARGET.md` v0.1 (компоненты и контракты). Идентификаторы `REQ-{slug}` сохранены из ingest (`.planning/intel/requirements.md`). Условия приёмки заданы явно только в `spec.md` §13, для остальных требований приёмка взята из текста правила, а при её отсутствии указано «отдельный критерий не задан».

Пометка **OQ-N** означает, что требование затронуто открытым вопросом владельца из `.planning/INGEST-CONFLICTS.md` (список и привязка к фазам в `.planning/STATE.md`). Ни один вопрос не решён.

## v1 Requirements

Требования MVP. Каждое привязано ровно к одной фазе (см. Traceability).

### Набор фишек

- [ ] **REQ-pieces-set**: 5 типов фишек базового набора, по 11 у каждой из двух команд (красная и синяя): `Sovereign` 1, `Climber` 2, `Jumper` 3, `Scout` 2, `Runner` 3. Фишки в движке называются по поведению, тема даёт имена и картинки отдельным файлом. Источник: spec §2, §4. Приёмка: в запасе каждой команды 11 фишек в указанном распределении.
- [ ] **REQ-engine-extensibility**: расширения набора (три дополнительные фишки) в MVP не реализуются, но новый тип фишки добавляется без переделки существующих. Источник: spec §4. Приёмка: отдельный критерий не задан.

### Поле и общие правила

- [ ] **REQ-board-geometry**: поле разбито на гексагоны, радиус 10 от центра, всего 331 клетка, острая вершина вверх; первая фишка партии ставится в центр. Источник: spec §2, §6. Приёмка: на поле ровно 331 клетка, клеток за радиусом 10 нет.
- [ ] **REQ-board-edge**: клеток за радиусом 10 не существует; выставление и движение за пределы поля недопустимы, ходы, требующие выхода за поле, не входят в список допустимых. Источник: spec §5.5. Приёмка: ни один допустимый ход не ведёт за пределы поля, есть тест на край поля (spec §10).
- [ ] **REQ-turn-order**: игроки ходят по очереди; первый ход определяется случайно, жребий бросает сервер при старте партии (в локальном режиме тоже случайно). Источник: spec §5.1. Приёмка: команда первого хода выбирается случайно на сервере при старте партии. Движок получает готовую команду в `Game.Start`.
- [ ] **REQ-turn-action**: за ход можно выставить новую фишку из запаса или переместить уже стоящую. Источник: spec §5.1. Приёмка: отдельный критерий не задан.
- [ ] **REQ-hive-unity**: все фишки на поле образуют единую группу; ход, при котором группа распадается, запрещён, в том числе когда разрыв возникает только после того, как фишка покинула своё место. Источник: spec §5.1. Приёмка: разрывающий ход не входит в список допустимых, есть тест разрыва группы (spec §10, §13 п.3).
- [ ] **REQ-slide-rule**: фишка, движущаяся по поверхности, не может протиснуться между двумя соседними фишками, если проход слишком узок; для `Climber` проверка учитывает высоты стопок; прыжок `Jumper` под правило не попадает. Источник: spec §5.1. Приёмка: есть тест протискивания, включая высоты (spec §10, §13 п.3). Уточнено 2026-10-27 (Phase 3 D-02, D-03, D-05): по земле из двух общих клеток занята ровно одна; для `Climber` шаг запрещён при `min(h1, h2) > max(hA, hB)`. OQ-2 закрыт.
- [ ] **REQ-crawl-touch-group**: каждый шаг ползущей фишки (`Sovereign`, `Scout`, `Runner`) заканчивается в клетке, касающейся группы (без учёта самой двигающейся фишки). Источник: spec §5.1. Приёмка: отдельный критерий не задан.
- [ ] **REQ-covered-piece-immobile**: фишка, на которую поднялась другая, не может двигаться; цвет стопки определяется верхней фишкой. Источник: spec §5.1. Приёмка: отдельный критерий не задан (в `ARCHITECTURE-TARGET.md` §4.4 правило явно не описано).

### Выставление

- [ ] **REQ-placement**: первая фишка первого игрока строго в центр; первая фишка второго игрока вплотную к первой; далее новая фишка в пустую клетку, которая касается хотя бы одной фишки своей команды и не касается фишек соперника. Источник: spec §5.2. Приёмка: отдельный критерий не задан. Уточнено 2026-10-27 (Phase 2 D-01..D-03, D-08, D-09): первая фишка второго игрока в любую из шести клеток вокруг центра; стопка учитывается по верхней фишке; только в пустую клетку; любой тип из запаса. OQ-6 и OQ-4 (стопка) закрыты.
- [ ] **REQ-sovereign-deadline**: `Sovereign` должен быть выставлен не позднее четвёртого хода игрока; пока король не выставлен, перемещать фишки нельзя. Источник: spec §5.2. Приёмка: есть тест выставления короля (spec §10). Уточнено 2026-10-27 (Phase 2 D-06): после трёх своих ходов без короля допустимо только его выставление; король разрешён первым ходом. OQ-4 закрыт.

### Движение фишек

- [ ] **REQ-move-sovereign**: `Sovereign` движется на 1 клетку скольжением. Источник: spec §5.3. Приёмка: тесты по фишке (spec §10).
- [ ] **REQ-move-climber**: `Climber` движется на 1 клетку, в том числе вверх на фишку, поверх фишек и вниз на пустую клетку. Источник: spec §5.3. Приёмка: тесты по фишке (spec §10). Уточнено 2026-10-27 (Phase 3 D-02, D-03): правило высот по `REQ-slide-rule`, по земле ходит как `Sovereign`. OQ-2 закрыт.
- [ ] **REQ-move-jumper**: `Jumper` движется по одному из 6 направлений через непрерывный ряд занятых клеток (минимум одна) на первую пустую; если она вне поля, прыжок недопустим. Источник: spec §5.3, ARCHITECTURE-TARGET §4.4. Приёмка: тесты по фишке (spec §10).
- [ ] **REQ-move-scout**: `Scout` делает ровно 3 шага, каждый шаг скольжением по земле вдоль края группы; путь состоит из 4 различных клеток, исходная считается пройденной, поэтому ход не заканчивается в исходной клетке; результат это различные конечные клетки. Источник: spec §5.3 (v0.4), ARCHITECTURE-TARGET §4.4. Приёмка: тесты по фишке (spec §10). Сведено 2026-10-27 из `REQ-move-scout-v1` и `REQ-move-scout-v2` (Phase 3 D-01). OQ-1 закрыт.
- [ ] **REQ-move-runner**: `Runner` выполняет любое число скольжений вдоль края группы; исходная клетка из результатов исключается. Источник: spec §5.3, ARCHITECTURE-TARGET §4.4. Приёмка: тесты по фишке (spec §10).

### Конец игры

- [ ] **REQ-win-condition**: победа, когда король соперника окружён фишками с шести сторон (любыми). Источник: spec §5.4. Приёмка: есть тест условия победы (spec §10).
- [ ] **REQ-draw-condition**: если окружены оба короля одновременно, объявляется ничья; ничья по повторению в MVP не входит. Источник: spec §5.4. Приёмка: есть тест условия ничьей (spec §10).
- [ ] **REQ-no-moves-loss**: пропуска хода нет; если у игрока в начале его хода нет ни одного допустимого выставления или перемещения (в том числе на 4-м ходу некуда выставить короля), ему засчитывается поражение; окружение королей проверяется раньше. Источник: spec §5.4 (v0.3). Приёмка: есть тест поражения при отсутствии ходов (spec §10). Заменяет `REQ-pass-turn` по решению владельца 2026-10-27 (Phase 2 D-04, D-05, D-07).

### Режимы, сеть, хранение

- [ ] **REQ-server-authority**: полная проверка правил только на сервере; клиент отправляет намерение (выставить или переместить), сервер проверяет, рассылает новое состояние и список допустимых действий; нелегальные ходы отклоняются. Источник: spec §2, §7, §10. Приёмка: spec §13 п.2. Уточнено 2026-10-27 (Phase 5 D-01, D-02): `status` в контракте `inProgress`/`won`/`draw`, `result` = `{ winner, reason }`. OQ-5 закрыт.
- [ ] **REQ-hotseat-mode**: локальный режим «два игрока за одним экраном» входит в MVP и реализуется первым, до сетевой части; запускается через сервер (ARCHITECTURE-TARGET §5.5, §11). Источник: spec §2, §3 п.5, §7, §12. Приёмка: spec §13 п.1 (полная партия от старта до победы или ничьей).
- [ ] **REQ-online-mode**: сетевая игра 1 на 1 через браузер; комнату создаёт одна сторона, вторая заходит по ссылке-приглашению. Источник: spec §2, §3 п.1, §7. Приёмка: spec §13 п.1.
- [ ] **REQ-anonymous-login**: анонимный вход, игрок вводит имя (до 24 символов), регистрации нет; сервер выдаёт токен, в БД хранится его SHA-256 хеш. Источник: spec §2, §7, ARCHITECTURE-TARGET §5.6. Приёмка: отдельный критерий не задан.
- [ ] **REQ-reconnect**: игрок, потерявший связь, возвращается в ту же партию, состояние восстанавливается из хранилища; обрабатываются отключение игрока и повторный вход. Источник: spec §3 п.4, §7, §10. Приёмка: spec §13 п.5 (партия не теряется при обрыве соединения).
- [ ] **REQ-game-storage**: партии хранятся в PostgreSQL как список ходов с первого дня (для повторов и анализа); интерфейса повтора и режима наблюдателя в MVP нет. Источник: spec §2, §7. Приёмка: отдельный критерий не задан.

### Интерфейс

- [ ] **REQ-highlight**: при выборе фишки допустимые клетки подсвечиваются зелёным и значком (точка), недопустимые красным и значком (крестик), но только клетки, прилегающие к группе; остальное поле нейтральное; цвет всегда сопровождается значком. Источник: spec §2, §6, §13 п.4. Приёмка: spec §13 п.4.
- [ ] **REQ-ui-widescreen**: только широкоформатный экран, целевое разрешение 1920×1080, масштабирование до 1366×768; поле при радиусе клетки около 28 px занимает порядка 1000×900 px; рендеринг в SVG. Источник: spec §2, §6. Приёмка: отдельный критерий не задан.
- [ ] **REQ-ui-panels**: панель запаса фишек каждого игрока, индикатор очереди хода, сообщение о результате; при выборе фишки краткое описание её движения; стопки отображаются верхней фишкой и счётчиком высоты; простые анимации перемещений. Источник: spec §6. Приёмка: отдельный критерий не задан.
- [ ] **REQ-theme-separation**: тема (идентификатор фишки, название, описание, изображение) хранится в отдельном файле, движок о ней не знает. Тема «Средневековье»: `Sovereign` король, `Climber` осадная башня, `Jumper` рыцарь, `Scout` разведчик, `Runner` гонец. Источник: spec §4, §8. Приёмка: смена оформления не затрагивает код правил.
- [ ] **REQ-graphics-assets**: векторная графика SVG, плоский геометричный стиль, только оригинальные образы; команды различаются не только цветом, но и формой щита, рамкой или узором. Ресурсы: 5 типов фишек × 2 команды, маркеры подсветки (точка, крестик), фон стола, значок осады короля; до готовности допустимы цветные заглушки. Источник: spec §9. Приёмка: отдельный критерий не задан.
- [ ] **REQ-original-assets-only**: нельзя копировать фишки, логотип, названия и тексты оригинальной игры; перед публичным релизом или монетизацией нужна консультация юриста. Источник: spec §9, §10. Приёмка: отдельный критерий не задан.

### Качество и готовность

- [ ] **REQ-engine-tests**: модульные тесты движка обязательны; покрытие: каждая фишка, единство группы, скольжение (включая высоты), победа и ничья, выставление короля, край поля, поражение при отсутствии ходов; случайные партии с проверкой инвариантов (группа связна, `Apply` не падает на допустимом ходе, `Replay` даёт то же состояние); любое изменение правил сопровождается тестом. Источник: spec §8, §10, §13 п.3, ARCHITECTURE-TARGET §9. Приёмка: spec §13 п.3 (тесты проходят, включая разрыв группы, протискивание, край поля).
- [ ] **REQ-mvp-done**: критерии готовности MVP: (1) полная партия локально и по сети от старта до победы или ничьей; (2) все ходы проверяются сервером, нелегальные отклоняются; (3) тесты движка проходят, включая разрыв группы, протискивание и край поля; (4) подсветка показывает допустимые и недопустимые клетки со значками; (5) партия не теряется при обрыве соединения. Источник: spec §13. Приёмка: выполнение всех пяти пунктов.

## v2 Requirements

Отложено за пределы MVP, не входит в текущий roadmap (`spec.md` §2). Чекбоксов нет: это не actionable-требования.

- Расширения набора фишек (три дополнительные фишки), точка расширения заложена в движке (`REQ-engine-extensibility`).
- Бот-соперник.
- Режим наблюдателя и интерфейс повтора партии (хранение ходов уже в MVP, `REQ-game-storage`).
- Ничья по повторению позиции.
- Регистрация с email и паролем, рейтинги, турниры.
- Таймеры хода и контроль времени, автопроигрыш по отсутствию.
- Отмена хода, звуки, чат, мобильная версия.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Мобильная версия, адаптивная вёрстка | Целевой экран только широкоформатный |
| Бот-соперник | В MVP играют только люди |
| Регистрация, рейтинги, турниры | Достаточно анонимного входа по имени |
| Таймеры хода, автопроигрыш | Не нужны для семейной игры, партия остаётся открытой |
| Отмена хода | Не требуется для MVP |
| Режим наблюдателя, интерфейс повтора | Ходы хранятся, интерфейс отложен |
| Ничья по повторению | Решение `spec.md` §12: после MVP |
| Звуки, чат | Не входят в MVP |
| Публичный релиз, монетизация | Нужна консультация юриста |
| Кнопка «сдаться» | Решение не принято (`ARCHITECTURE-TARGET.md` §13), в требования не включена |
| Копирование названий, текстов, графики оригинальной игры | Юридический запрет (`spec.md` §9) |
