# Phase 3: M2 Движение фишек, единство группы, скольжение - Context

**Gathered:** 2026-10-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Движок `Siege.Engine` перечисляет (`Game.GetLegalMoves`) и применяет (`Game.Apply`) перемещения всех пяти фишек (`Sovereign`, `Climber`, `Jumper`, `Scout`, `Runner`) с проверкой единства группы, скольжения (включая высоты для `Climber`), касания группы, края поля и неподвижности накрытой фишки. Случайные партии проверяют инварианты. Победа, ничья, поражение без ходов, сериализация и `Replay` относятся к Phase 4.

Требования: `REQ-board-edge`, `REQ-hive-unity`, `REQ-slide-rule`, `REQ-crawl-touch-group`, `REQ-covered-piece-immobile`, `REQ-move-sovereign`, `REQ-move-climber`, `REQ-move-jumper`, `REQ-move-scout` (сводится из `REQ-move-scout-v1` и `REQ-move-scout-v2` по D-01), `REQ-move-runner`.

Фаза зависит от типов Phase 2 (`GameState`, `Move`, `RelocateMove`, `Game`). На 2026-10-27 Phase 2 ещё не реализована, в движке есть только `Hex`.

</domain>

<decisions>
## Implementation Decisions

Все решения о правилах ниже обратимы, пока ходы не хранятся в БД. **Reversibility:** costly после Phase 6: смена правила движения делает сохранённые партии невоспроизводимыми через `Replay` (`ARCHITECTURE-TARGET.md` §11, «только ходы»), понадобится миграция данных или версия правил.

### Scout: возврат на клетки (OQ-1, закрыт)
- **D-01:** Путь `Scout` состоит из 4 различных клеток: исходная и три новые. Исходная клетка считается посещённой с самого начала, поэтому через неё нельзя пройти и в ней нельзя закончить ход. Каждый из трёх шагов это шаг по земле по D-05 на поле без самого `Scout`. Результат: множество различных конечных клеток. Принимается вариант `REQ-move-scout-v1` в уточнённой форме, `REQ-move-scout-v2` снимается, оба сводятся в одно требование `REQ-move-scout`.

### Climber: правило высот (OQ-2, закрыт)
- **D-02:** Шаг `Climber` из A в соседнюю B запрещён, если `min(h1, h2) > max(hA, hB)`, где `hA` это высота стопки в A без самого `Climber`, `hB` это высота стопки в B, `h1` и `h2` это высоты двух общих соседних клеток A и B (пустая клетка и клетка вне поля имеют высоту 0). Иначе говоря, обе общие стопки выше и клетки отправления, и клетки прибытия.
- **D-03:** Когда `hA = 0` и `hB = 0` (шаг по земле), `Climber` дополнительно подчиняется правилу контакта D-05, то есть ходит по земле как `Sovereign`. При подъёме и спуске контакт с группой сохраняется сам (одна из клеток A и B занята), отдельной проверки нет. Цель шага: любая из шести соседних клеток в пределах поля, занятая или пустая.
- **D-04:** Первоисточник правил это `docs/spec.md`. Ссылки на «официальные правила» в `spec.md` §5.1 и `ARCHITECTURE-TARGET.md` §4.4 убираются. `ARCHITECTURE-TARGET.md` §12 закрывается целиком: п.1 по D-02, п.4 по D-01.

### Шаг вдоль края группы
- **D-05:** Шаг по земле из A в соседнюю пустую B (поле считается без двигающейся фишки) допустим, если из двух общих соседних клеток A и B занята **ровно одна**. Обе заняты: проход слишком узок. Обе пусты: фишка теряет контакт с группой, шаг недопустим, даже если B касается группы через другую клетку. Клетка вне поля считается пустой, а сама B обязана существовать (радиус из `GameOptions`). Правило действует для `Sovereign`, `Scout`, `Runner` и для `Climber` на земле (D-03). Прыжок `Jumper` ему не подчиняется.
- **D-06:** Из D-05 следует `REQ-crawl-touch-group`: B всегда касается группы через занятую общую клетку. Отдельная проверка касания в коде не обязательна, но тест на «перескок через пустоту» обязателен.

### Тесты
- **D-07:** Позиции в тестах задаются билдером в коде, например `Position().At(0, 0, Red, Sovereign).At(1, 0, Blue, Climber)`. Повтор одной клетки добавляет фишку в стопку снизу вверх. Строкового или ASCII-формата не делаем.
- **D-08:** Случайные партии: около 200 партий по 100 ходов максимум, с фиксированными seed, в обычном прогоне `dotnet test` (`Random` только в тестовом проекте, движок остаётся детерминированным). При падении в сообщение пишутся seed и номер хода. Инварианты Phase 3: после каждого хода группа связна, `Apply` не бросает исключение на ходе из `GetLegalMoves`, ни одна фишка не стоит за пределами поля. Равенство результата `Replay` добавляется в Phase 4.

### Документы
- **D-09:** Решения D-01..D-06 переносятся в документы сразу после записи этого CONTEXT.md, до `/gsd-plan-phase 3`:
  - `docs/spec.md`: §5.1 (скольжение, контакт, формула высот), §5.3 (`Scout`), журнал §12, шапка «v0.4, открытых вопросов по правилам нет»;
  - `.planning/ARCHITECTURE-TARGET.md`: §4.4 (скольжение, `Climber`, `Scout`), запись в журнале §11, §12 закрыт;
  - `.planning/REQUIREMENTS.md`: `REQ-move-scout-v1` и `REQ-move-scout-v2` сводятся в `REQ-move-scout`, у `REQ-slide-rule` и `REQ-move-climber` снимаются пометки OQ-2;
  - `.planning/ROADMAP.md` и `.planning/STATE.md`: OQ-1 и OQ-2 отмечаются закрытыми.

### Claude's Discretion
- Как билдер позиций создаёт `GameState` в обход правил выставления: `internal`-фабрика с `InternalsVisibleTo("Siege.Engine.Tests")` или публичный метод. Важно, чтобы у движка не появилось `ProjectReference` и `PackageReference` (`.claude/rules/engine.md`). Билдер должен уметь задать, чья очередь и выставлены ли короли (иначе перемещения запрещены правилом Phase 2).
- Форма перемещений в `GetLegalMoves`: одна `RelocateMove(From, To)` на пару клеток (разные пути `Runner` и `Scout` к одной цели схлопываются), порядок списка любой детерминированный.
- Алгоритм единства группы: точки сочленения (Тарьян) один раз на позицию, как в `ARCHITECTURE-TARGET.md` §4.4; фишка на вершине стопки высотой 2 и больше правило не нарушает.
- Разбиение правил движения по типам (точка расширения `REQ-engine-extensibility` из Phase 2) и раскладка тестов по файлам `<Тип>Tests.cs`.

Две общие соседние клетки A и B получаются из соседних по индексу направлений относительно направления A→B (`ARCHITECTURE-TARGET.md` §4.1), отдельного метода пока нет.

### Established Patterns
- Пространство имён `Siege.Engine`, file-scoped, один публичный тип на файл, XML-doc на русском.
- `TreatWarningsAsErrors` включён, `dotnet format --verify-no-changes` входит в проверку.
- Ход проверяется только через членство в `GetLegalMoves`, у `Apply` нет второго набора правил.

- Перемещения встраиваются в `Game.GetLegalMoves` и `Game.Apply` из Phase 2 как `RelocateMove(From, To)`.

<specifics>
## Specific Ideas

- Формула `Climber` выбрана так, чтобы на земле она совпадала с правилом D-05. Тесты должны показать, что ход `Climber` по земле совпадает с ходом `Sovereign` в той же позиции.
- `Climber` может подняться на любую фишку, в том числе на короля соперника (`spec.md` §5.3 ограничений не вводит). Накрытый король не двигается, а его окружение для победы считается в Phase 4.

</specifics>
